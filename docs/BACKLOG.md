# SimpleSport — список задач по приоритету

> Источник требований: [BUSINESS-PLAN.md](./BUSINESS-PLAN.md), версия 1.4. Этот файл — рабочая очередь, а не
> спецификация: постановка задачи всегда читается в плане по ссылке в колонке «План».
>
> **Порядок приоритета — сверху вниз.** Он продиктован зависимостями, а не важностью для пользователя: без Этапа 1 не
> строится ничего, без ленты нет главного экрана, без подходов нет тоннажа.

## Как читать

**Размер** — грубая оценка, нужна только для планирования порядка внутри этапа, не для сроков.

| Метка | Значение                                            |
| ----- | --------------------------------------------------- |
| **S** | до одного дня                                       |
| **M** | один-три дня                                        |
| **L** | больше трёх дней, стоит разбить при взятии в работу |

**Статус** проставляется прямо здесь: `[ ]` не начато, `[~]` в работе, `[x]` готово.

Задачи с пометкой **⛔** блокируют всё, что ниже них в своём этапе.

## Этап 1 — Фундамент: модель данных и архитектура ← текущий приоритет

Эпик 1 и раздел 8 идут одной работой: они переписывают один и тот же код, и разносить их по этапам означало бы трогать
его дважды.

**Критерий готовности этапа.** Существующие экраны переведены на новую схему и архитектуру и работают без регрессий.
Тоннаж считается корректно на тестовых данных. Правка упражнения в справочнике сама подхватывается лентой без ручного
`reload`. Чеклист 8.9 проходит.
